技術仕様サマリー：EXEレス BiDi の仕組み

📖 登場秘話 で語られた「発見の旅」を経て、なぜこの構成が機能するのか——その技術的なエッセンスを簡潔にまとめます。

🗺️ アーキテクチャ全体像

外部 exe も Node.js も不要。VBA ↔ ブラウザ内JS の2者間で完結します。

📊 VBA BiDi JSON を組み立て・送信 ↕ 標準入出力パイプ
--remote-debugging-pipe 🌐 mapperTab.js (隠しタブ) BiDi ↔ CDP を翻訳するエンジン ↕ window.cdp (特権オブジェクト) ⚙️ Chromium エンジン 実際のブラウザ操作を実行

🔧 初期セットアップ（3つの CDP コマンド）

起動時に以下を順番に実行することで、VBA ↔ mapperTab.js の通信路が確立されます。

#CDP コマンド役割
① Target.exposeDevToolsProtocol 隠しタブに window.cdp という「CDP特権オブジェクト」を露出。mapperTab.js が自分自身へCDP命令を打てるようになる。
② Runtime.addBinding sendBidiResponse という関数をJSに登録。mapperTab.js の結果を VBA 側へ「逆流」させるブリッジを構築する。
③ Runtime.evaluate Excelのセルに格納した mapperTab.js のソースを注入・起動。翻訳エンジンが稼働開始する。

🔄 コマンド送受信のフロー

セットアップ完了後、各 BiDi コマンドは以下のサイクルで処理されます。

① VBA → Runtime.evaluate で onBidiMessage(jsonStr) を呼び出す
↓ mapperTab.js がBiDiコマンドを受信
② JS → window.cdp を通じてChromiumへCDP命令を発行
↓ Chromiumがコマンドを実行
③ JS → sendBidiResponse(resultJson) (Binding) で結果を返却
↓ Runtime.bindingCalled イベントが発火
④ VBA → TakeEvents でバッファを回収・解析して完了

📦 mapperTab.js の調達方法

翻訳エンジン本体は Chromium公式チームが提供しており、VBAから自動取得できます。

jsDelivr CDN 経由で自動ダウンロード

https://cdn.jsdelivr.net/npm/chromium-bidi/... のAPIを WinHTTP 5.1 で叩き、最新バージョンを取得。テキストデータなのでExcelのセルに格納できます。

バイナリ（exe）ではなくテキストデータなので情シスのウイルスチェックをすり抜け、配布・更新が容易です。

✅ 公式ドライバーとの同一性（検証済み）

msedgedriver.exe をバイナリエディタで開いたところ、内部に <!DOCTYPE html><title>BiDi-CDP Mapper</title>... という文字列がハードコードされていることが確認できました。

つまり、公式ドライバーも 内部で全く同じアプローチ（mapperTab.js を隠しタブに注入）を採用しています。詳細は 📖 登場秘話 をご覧ください。
