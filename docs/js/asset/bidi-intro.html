WebDriver BiDi コーナー：未来的な思考

技術的な仕組み：何故、WebDriverBiDi.exe なしで動くのか？

外部ツールの chromedriver.exe や Selenium を 一切使用せずに、VBA 単体で「WebDriver BiDi プロトコル」によるブラウザ操作を実現している驚くべきアーキテクチャの裏側を解説します。

1. そもそも WebDriver BiDi とは？

従来の自動化では、同期通信中心の「Selenium (WebDriver)」と、強力だがGoogle独自の「CDP」という2つのアプローチがありました。
WebDriver BiDi は、これら両者の「いいとこ取り」をした次世代の W3C 標準プロトコルです。双方向のイベント通信（Bidirectional）を標準化し、すべての主要ブラウザで等しく動作する高速な非同期通信を目指しています。

2. WebDriver レスの実現方法（パイプライン）

本来、WebDriver BiDi を使うためには専用の「仲介サーバー（chromedriver 等）」を立ち上げるのが一般的ですが、当プロジェクトの WebDriverBiDiCore.cls では以下の手法により VBA からブラウザへ完全に直結 しています。

1️⃣
CDP パイプ通信による初期接続

起動時に --remote-debugging-pipe を付与し、OS標準機能の「標準入出力のパイプ通信」を通じて直接対話できる経路を作ります。

2️⃣
BiDi マッパー (mapperTab.js) の注入

Google公式が提供する「CDP ↔ BiDi」変換スクリプトを、作成した裏側のタブ空間にインジェクト（注入）し、専用の直通メッセージラインを構築します。

3️⃣
VBA ↔ BiDi の完全通信の確立

以降、VBA からマッパーに対して browsingContext.navigate 等の標準 BiDi の JSON を直接流し込むことが可能になります。

圧倒的なメリット

  • 環境非依存（完全ポータブル）: Excelさえ動けば、追加インストール不要ですぐに動きます。
  • 超低レイテンシ: 中間サーバーを経由しないため、極限まで素早いレスポンスを誇ります。
  • JSONの高速フィルタリング: BiDiCore.cls 内部で高負荷な ParseJson 前に InStr 判定を行うことで、VBA 特有の遅さをスマートに克服しました。
