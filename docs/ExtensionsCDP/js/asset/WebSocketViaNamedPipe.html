WebSocketViaNamedPipe 拡張機能

概要

CDPCore.cls の標準通信方式は remote-debugging-pipe（匿名パイプ） です。 これは高速・低レイテンシである一方、Chromium プロセスとの直接パイプ接続（VBAからブラウザを起動すること）が前提となります。

この拡張機能は、WebSocket（ws://）経由で外部 Chromium に接続したい場合のために用意されています。 VBA の名前付きパイプと PowerShell の WebSocket クライアントの間に 中継レイヤー を挟むことで、 既存の CDPCore.cls を変えずにそのまま利用できるようになります。

WebSocket だからこそできること

remote-debugging-pipe は高速ですが、同一 PC 上の Chromium プロセスとの直接接続に限られます。 WebSocket 経由にすることで、以下のようなニッチなシナリオにも対応できます。

📱 Android スマートフォンの Chromium を自動制御

Android 実機の Chrome を PC から CDP 操作できます。

セットアップ例 
# adb でポートをフォワード
adb forward tcp:9222 localabstract:chrome_devtools_remote

# WebSocket URL を確認
# → http://127.0.0.1:9222/json/version の webSocketDebuggerUrl を使う

Android の Chrome を USB デバッグ対象にするには、Chrome の「デバッグを許可」設定と Android の開発者オプション「USB デバッグ」を有効にする必要があります。

🪟 WebView2 をリモートデバッグポート経由で制御

WebView2 アプリを CDP で操作するには、環境変数 WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS に --remote-debugging-port=9222 を付与して起動します。

WebView2 制御の鍵

CDPCore.cls のデフォルト起動（匿名パイプ）では、他アプリ内の WebView2 は操作できません。この拡張機能を使うことで、外部アプリ内の WebView2 も VBA から制御が可能になります。

🖥️ 「今起動中のブラウザ」を後付けで自動操作

最新のブラウザ機能により、「既に開いている通常のブラウザウィンドウ」 を後付けで制御できるようになりました。

設定方法（Edge の場合）:

  1. Edge で edge://inspect/#remote-debugging を開きます。
  2. 「Allow remote debugging for this browser instance」 を ON にします。
  3. 接続に必要な情報は %LOCALAPPDATA%\Microsoft\Edge\User Data\DevToolsActivePort に出力されます。

通信フロー

データ送信（VBA → Chrome）

sequenceDiagram participant V as VBA（CDPCore） participant P as PowerShell participant C as Chrome V->>P: JSON + Null バイト(\0) をパイプへ書き込み P->>P: ReadAsync で受信
Null バイトでメッセージ境界を判定 P->>C: WebSocket.SendAsync で転送 C->>C: CDP コマンドを処理

データ受信（Chrome → VBA）

sequenceDiagram participant C as Chrome participant P as PowerShell participant V as VBA（CDPCore） C->>P: WebSocket でレスポンス送信 P->>P: ReceiveAsync で受信 P->>V: パイプへ書き込み P->>V: EndOfMessage なら Null バイト(0x00) を追加して Flush V->>V: Null バイトでメッセージ終端を検出

セットアップ手順

Step 1：ブラウザ（Chromium）を準備する

方法A：起動オプション --remote-debugging-port=9222 を付与して起動。

方法B：起動中のブラウザで edge://inspect/#remote-debugging を開き許可する。

Step 2：接続ブリッジの起動（パターン選択）

パターンA：手動実行（ManualSetup）

ウイルス対策ソフトの誤検知リスクが低く、安全な方法です。

  1. PowerShell で StartWebSocket.ps1 を実行。
  2. GUI セレクト画面で接続先を選択。
  3. VBA から ManualSetup を実行。
⚙️
パターンB：自動実行（AutoSetup）

PowerShell コードを Excel 内に保持し、VBA から自動呼び出しします。ウイルス対策ソフトにブロックされる可能性がありますが、ボタン一つで完結します。

Step 3：CDP 操作を開始する

Sub WebSocketにてCDPの始まり()
    Dim WebSocketCDP As New CDPBrowser

    ' まず targetID に再接続を試みる
    If Not WebSocketCDP.reattach("ChromiumWebSocket") Then
        ' 失敗した場合は新規接続
        WebSocketCDP.getTab setMain:=True
    End If

    ' 通常の CDPBrowser と同様に操作可能
    WebSocketCDP.navigate "https://example.com"
    
    WebSocketCDP.quit
End Sub

内部設計メモ

WriteThrough フラグ

PowerShell 側で名前付きパイプを作成する際、WriteThrough オプションを指定しています。 これにより OS レベルのバッファリングを無効化し、VBA 側が即座にデータを受信できるように設計されています。 

$pipeOptions = [System.IO.Pipes.PipeOptions]::WriteThrough -bor [System.IO.Pipes.PipeOptions]::Asynchronous
🛑
リソースの解放について

Excel テーブルに記録されていないパイプハンドルは破棄できません。接続エラーが続く場合は、Excel プロセスの再起動が必要になることがあります。終了時は必ず cleanNamedPipe() を呼び出してください。
