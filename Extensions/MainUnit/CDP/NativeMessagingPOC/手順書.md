# chrome.debugger × Native Messaging によるCDP制御 セットアップ手順書

このフォルダは、`StarterWebScrapingKit`にChrome拡張機能(`chrome.debugger`)×Native Messaging経由のCDP制御を追加するための、VBA以外の構成ファイル一式です。

- `Extension/` … 拡張機能本体(`manifest.json` / `background.js`)。**ChromeとEdge(Chromium系)の両方に、無改造でそのまま読み込めます**
- （生成物）ホストマニフェスト(.json)、ラッパー`.bat` … `src/modules/NativeMessagingSetup.bas`のマクロで生成します

VBA側の実体（`CDPCoreViaNativeMessaging.cls` / `CDPCore.cls` への結線 / `CDPBrowser.reattachNativeMessaging`）は`src/classes`にあります。

**このドキュメントは、ChromeとEdgeの両方の手順を併記しています。今回はEdgeで実験する場合、各ステップの「Edge」の指示に従ってください。**

---

## 0. 全体構成

```
ブラウザの拡張機能(chrome.debugger) ──stdin/stdout(Native Messaging)── Excel(VBA: CDPCoreViaNativeMessaging.cls)
```

Native Messagingは仕様上、拡張機能が`chrome.runtime.connectNative`した瞬間に、OS側(レジストリ)に登録されたホスト実行ファイルをブラウザ自身が起動し、そのプロセスの標準入出力を直接パイプで掴みます。このプロジェクトでは、そのホスト実行ファイルとして**Excel自身**を登録します(`EXCEL.EXE`直接、または`/x`起動するラッパー`.bat`経由の2択)。

**ChromeとEdgeの違いについて**: EdgeもChromiumベースのため、Native Messagingのワイヤーフォーマット(4バイト長プレフィックス+UTF-8 JSON、1MiB/4GB上限)、起動時に渡される引数(`chrome-extension://<id>/`, `--parent-window=<handle>`)、ホストマニフェストJSONの書式(`allowed_origins`が`"chrome-extension://<id>/"`のままである点も含む)は、[Microsoft公式ドキュメント](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)で確認した限り**Chromeと完全に同一**です。**違うのはレジストリの登録先パスと、拡張機能ID(ブラウザごとに別々に発行される)だけ**です。

**重要な既知リスク**: ブラウザが渡す引数(`chrome-extension://<id>/`, `--parent-window=0`)をExcelがファイルパスとして誤解釈しエラーダイアログが出る可能性、およびExcelの既定DDEシングルインスタンス動作により新規プロセスが既存インスタンスに処理を委譲して即終了する可能性があります。**§3で先に検証してから本運用してください。**

---

## 1. 拡張機能を読み込む

- **Chromeの場合**: `chrome://extensions` を開く
- **Edgeの場合**: `edge://extensions` を開く

共通の手順:
1. 「デベロッパーモード」をON(Edgeの場合は左側メニュー内のトグル)
2. 「パッケージ化されていない拡張機能を読み込む(Load unpacked)」→ `NativeMessagingBridge\Extension` フォルダを選択
3. 表示された**拡張機能ID**(32文字の英字)をメモしておく
   - ※このIDは、拡張機能をリロードする度に変わりうる点に注意（`manifest.json`に`"key"`を追加して固定する方法もあります）
   - ※ChromeとEdgeで同じ拡張機能フォルダを読み込んでも、**IDはブラウザごとに別々に発行されます**。両方使う場合はそれぞれメモしてください

---

## 2. ホストマニフェストを生成する

Excel VBAのイミディエイトウィンドウ、または任意のマクロから、対象ブラウザ・方式に合わせて以下のいずれかを実行します。

| ブラウザ | オプションA(Excel.exe直接) | オプションB(ラッパーBAT経由・推奨) |
|---|---|---|
| Chrome | `Demo_NativeMessaging.GenerateNativeHostFiles_Chrome_直接Excel` | `Demo_NativeMessaging.GenerateNativeHostFiles_Chrome_ラッパーBAT経由` |
| Edge | `Demo_NativeMessaging.GenerateNativeHostFiles_Edge_直接Excel` | `Demo_NativeMessaging.GenerateNativeHostFiles_Edge_ラッパーBAT経由` |

実行するとダイアログで拡張機能IDの入力を求められます。1.でメモした、**対象ブラウザ側の**IDを入力してください。

生成先は既定でブラウザごとに分かれます:
- Chrome: `%LOCALAPPDATA%\StarterWebScrapingKit\NativeMessaging\Chrome\`
- Edge: `%LOCALAPPDATA%\StarterWebScrapingKit\NativeMessaging\Edge\`

- `com.starterwebscrapingkit.cdpbridge.json` … ホストマニフェスト(内容はChrome/Edgeで同一形式。`allowed_origins`のIDのみ異なる)
- （オプションBの場合のみ）`launch_excel_host.bat` … ラッパー

**オプションBを使う場合の注意**: `GenerateNativeHostFiles_○○_ラッパーBAT経由`は、実行した時点の`ThisWorkbook.FullName`をバッチに焼き込みます。**XLStartへ配置する「コピー」のワークブックから実行してください**（元のワークブックから実行すると、コピーではなく元ファイルの方が起動されてしまいます）。

## 3. 【先にやる】直接ホスト方式・BAT方式、どちらが動くかの検証

本実装に頼る前に、以下の最小プローブで実際にExcelが起動されるかを確認します。この検証はChrome/Edge共通です(§0の通り、渡される引数の形式は同一のため)。

### 3-1. 最小プローブワークブックの準備

1. 新規の空Excelブック(`.xlsm`)を作成
2. `ThisWorkbook`モジュールに、以下だけを書く

```vb
Private Sub Workbook_Open()
    Dim f As Integer: f = FreeFile
    Open "C:\Temp\xlstart_probe.log" For Append As #f
    Print #f, Now & " - Workbook_Open fired. CommandLine args: " & Command$
    Close #f
End Sub
```

3. `%APPDATA%\Microsoft\Excel\XLStart\` に保存する（フォルダがなければ作成）
4. `C:\Temp` フォルダを作成しておく

### 3-2. オプションA(直接)の検証

Excelを完全に終了(タスクマネージャーで`EXCEL.EXE`が残ってないか確認)した状態で、通常の(管理者権限でない)コマンドプロンプトから、ブラウザが実際に渡す引数を再現して実行します。

```bash
"C:\Program Files\Microsoft Office\root\Office16\EXCEL.EXE" "chrome-extension://aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa/" "--parent-window=0"
```

（EXCEL.EXEのパスはご自身の環境に合わせてください。`Application.Path`で確認できます。この引数の形式はChrome/Edge共通です）

確認項目:
- (a) `xlstart_probe.log`に新しい行が追記されるか（`Workbook_Open`が発火したか）
- (b) 何らかのエラーダイアログが出るか、出た場合ログの追記より前か後か
- (c) タスクマネージャーで`EXCEL.EXE`プロセスが起動したまま残るか、それとも一瞬で消えるか（DDE委譲で即終了していないか）

### 3-3. オプションB(ラッパーBAT)の検証

同様に、Excelを完全に終了した状態で、生成した`launch_excel_host.bat`を直接ダブルクリック(またはコマンドプロンプトから実行)し、同じ(a)(b)(c)を確認します。バッチはブラウザの引数を受け取らずに固定のコマンドラインでExcelを起動するため、(b)は発生しないはずです。

### 3-4. 判定

- (a)が発火し、(c)でプロセスが生き残るオプションを採用してください
- 両方失敗する場合は、Excelのオプション「ファイル」→「オプション」→「詳細設定」→「全般」の
  「**DDEを使う他のアプリケーションを無視する**」にチェックを入れてから再検証してください

## 4. Windowsレジストリへの手動登録

管理者権限は不要です(`HKEY_CURRENT_USER`配下のみ)。

### Chromeの場合

1. `regedit.exe`を起動
2. `HKEY_CURRENT_USER\SOFTWARE\Google\Chrome\NativeMessagingHosts\` に移動
3. 右クリック→新規→キーを作成し、名前を **`com.starterwebscrapingkit.cdpbridge`** とする（`manifest.json`の`"name"`と完全一致させること）
4. 作成したキーを選択し、`(既定)`の値を、2.で生成した**マニフェストJSONファイルのフルパス**に設定する
   - 例: `%LOCALAPPDATA%\StarterWebScrapingKit\NativeMessaging\Chrome\com.starterwebscrapingkit.cdpbridge.json`
5. `chrome://extensions`で拡張機能をリロードし、IDが変わっていないか確認（変わった場合は、マニフェストJSON内の`allowed_origins`を書き直し、§2をやり直す）

コマンドプロンプトから一括登録したい場合（管理者権限不要）:

```bash
reg add "HKCU\Software\Google\Chrome\NativeMessagingHosts\com.starterwebscrapingkit.cdpbridge" /ve /t REG_SZ /d "%LOCALAPPDATA%\StarterWebScrapingKit\NativeMessaging\Chrome\com.starterwebscrapingkit.cdpbridge.json" /f
```

### Edgeの場合

Chromeとほぼ同じ手順ですが、レジストリのパスが `Google\Chrome` ではなく **`Microsoft\Edge`** になります（[Microsoft公式ドキュメント](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)で確認済み）。

1. `regedit.exe`を起動
2. `HKEY_CURRENT_USER\SOFTWARE\Microsoft\Edge\NativeMessagingHosts\` に移動
3. 右クリック→新規→キーを作成し、名前を **`com.starterwebscrapingkit.cdpbridge`** とする
4. 作成したキーを選択し、`(既定)`の値を、2.で生成した**マニフェストJSONファイルのフルパス**に設定する
   - 例: `%LOCALAPPDATA%\StarterWebScrapingKit\NativeMessaging\Edge\com.starterwebscrapingkit.cdpbridge.json`
5. `edge://extensions`で拡張機能をリロードし、IDが変わっていないか確認（変わった場合は、マニフェストJSON内の`allowed_origins`を書き直し、§2をやり直す）

コマンドプロンプトから一括登録したい場合（管理者権限不要）:

```bash
reg add "HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.starterwebscrapingkit.cdpbridge" /ve /t REG_SZ /d "%LOCALAPPDATA%\StarterWebScrapingKit\NativeMessaging\Edge\com.starterwebscrapingkit.cdpbridge.json" /f
```

**参考**: Edgeは自分専用のキーが見つからない場合、`Chromium\NativeMessagingHosts`→`Google\Chrome\NativeMessagingHosts`の順にフォールバックして探しにいく仕様が公式ドキュメントに明記されています。ただし将来の仕様変更に依存したくないため、**Edgeで使う場合は上記のEdge専用キーを明示的に登録することを推奨**します。

---

## 5. XLStartへの本番配置

1. `StarterWebScrapingKit`のワークブック(`CDPCoreViaNativeMessaging.cls`, `CDPCore.cls`, `CDPBrowser.cls`等が既にインポート済みのもの)の**コピー**を用意する
2. そのコピーの`ThisWorkbook`モジュールに、以下を追加する

```vb
Private Sub Workbook_Open()
    Demo_NativeMessaging.StartNativeMessagingHostLoop
End Sub
```

3. コピーを `%APPDATA%\Microsoft\Excel\XLStart\` に配置する
4. オプションBを使う場合は、**このコピーから**`Demo_NativeMessaging.GenerateNativeHostFiles_Chrome_ラッパーBAT経由`(またはEdge版)を再実行し、`ThisWorkbook.FullName`をこのコピーのパスで焼き直す

## 6. 動作確認

1. 対象ブラウザ(Chrome/Edge)で任意のタブを開く
2. 拡張機能管理ページのツールバーで、読み込んだ拡張機能のアイコンをクリックする
   - （ツールバーに表示されない場合は、パズルピースアイコン→ピン留め）
3. 拡張機能アイコンをもう一度クリックすると、そのタブへの接続/切断がトグルされます（`chrome.debugger`の「このブラウザをデバッグしています」というインフォバーが表示されます。Edgeでも同様の文言のインフォバーが出ます）
4. 初回クリック時に、XLStartのExcelコピーが新規プロセスとして起動し、`StartNativeMessagingHostLoop`が実行されます
5. `%TEMP%\StarterWebScrapingKit_NativeMessaging.cdp.log`（および`.NativeMessaging.log`）で、接続確認(`Browser.getVersion`)が成功しているかを確認してください

### 段階的な検証の勧め

いきなり本命のCDPコマンドを試す前に、以下の順で確認すると原因切り分けがしやすいです。

1. **プラグ確認**: §3のプローブで、Excelが実際に新規起動されるか
2. **疎通確認**: 拡張機能詳細ページ→「Service Worker」の「検証(inspect)」でDevToolsコンソールを開き、`[CDPBridge] Native Messagingホストに接続しました`のログが出るか。出ない場合は「Specified native messaging host not found」等のエラーがないか確認（`allowed_origins`のID不一致、レジストリパス誤り(ChromeキーとEdgeキーの取り違え含む)が典型原因）
3. **CDP往復確認**: `%TEMP%\StarterWebScrapingKit_NativeMessaging.cdp.log`で`Browser.getVersion`の結果が記録されているか
4. **セッション多重化確認**: 対象タブに別オリジンの`<iframe>`があるページを開き、`Target.attachedToTarget`イベント(`sessionID`付き)が記録されているかを確認

### 既知の制限事項

- `chrome.debugger.attach`により、ブラウザ標準の「デバッグ中」インフォバーが必ず表示されます(非表示にはできません)
- Native Messagingの**ホスト→ブラウザ方向は1メッセージあたり最大1MiB**の制限があります。`Page.captureScreenshot`等、大きな結果を返すCDPコマンドで超過する可能性があるため、実測して問題があれば分割送信等の対応を検討してください
- デバッガセッション(タブ)ごとに新規Excelプロセスが起動する構成のため、複数タブを同時制御すると、その分だけExcelプロセスが並行起動します
- 同じ拡張機能フォルダをChromeとEdge両方に読み込んで併用する場合、双方のIDを`allowed_origins`に含めた1つのマニフェストを作る(手動編集)か、ブラウザごとに別々のマニフェスト(本手順のようにフォルダを分ける)で運用してください
